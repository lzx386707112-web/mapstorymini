# 原端玩法逻辑核对与单机迁移

日期：2026-10-21。依据为本机 `/Users/lizixian/Documents/mxd/BeiDou-Server/gms-server/src/main/java/org/gms/` 与 `clien/Data`，原端文件只读。

**这是职责收口和部分已核实规则的落地，不是完整原游戏 1:1。** 原端也不是“服务端计算一切”：普通攻击包携带客户端算出的伤害，服务端验证、封顶、扣血并结算。不能把反作弊伤害上限当作客户端的实际随机伤害公式。

| 伤害入口 | `CombatRules.Resolve` 统一处理整数伤害、暴击标记和初始个人伤害上限 19,999,999；怪物/Boss 消费相同的 `DamageResult`，不在受击时再次抽暴击。删除全职业统一 18%/1.7 倍暴击及 Boss 硬直 1.25 倍增伤；死亡后重复受击无效 | `server/DamageCapService.java`、`server/life/Monster.java` 的 applyAndGetHpDamage、`net/server/channel/handlers/AbstractDealDamageHandler.java` |

## 技能语义修正与边界

- 防御崩坏走驱散/封技路径，不造成横扫伤害；当前怪物尚无增防/免疫增益系统，因此不能据此声称已完成所有驱散效果。
- 圣光恢复为魔法攻击，移除自我治疗；愤怒之火使用 WZ 的固定攻击增益与持续时间，移除 +60%/6 秒设定。固定增益现已加入 WATK 属性池；完整边界见下文第二阶段。
- 磁石不造成范围伤害或眩晕，只处理普通怪的拉近；Boss 不被拉动。拉近运动仍为单机适配，未核实原客户端运动曲线。
- 技能伤害段数、目标数、MP、冷却、攻击框和控制时长读取 Lv.1 参数；虎咆哮按概率眩晕，连环爆破按原 StatEffect 的冻结类状态使用双倍时长。现有 Stun 只提供停止行动的基础效果，尚未实现完整怪物状态系统。
- 剑影分身使用独立子技能 1121021/1121022，并按 `CloseRangeDamageHandler` 的 12 次斩击与 5 次爆炸时间表安排延迟攻击；斗气死亡断层延迟 1000ms 命中。
- 天秤之使改为有持续时间的周期攻击，召唤间隔取原 summon/attack1 帧延时与 attackAfter。现已实现独立实体、跟随、寻敌和原帧动画，详见第二阶段。
- 突进已移除自定义无敌帧，使用原技能攻击参数与推怪路径；角色自身突进与碰撞现已接入，原 EXE 参数核实边界见第二阶段。
- 动作锁沿用当前原帧时长；完整武器攻速、硬直、跳跃施法限制尚未核实。

金币数据来自 `src/main/resources/db/migration/V1.0.51__drop_data_insert_old_data.sql` 的基础快照，抽取规则为 `nextInt(999999) < chance`、数量 `[minimum, maximum)`。当前按基础 1 倍计算，**未重建所有后续数据库迁移、运行中的数据库或服端倍率/Buff/卡片修正**。当前只迁移金币掉落，未迁移装备、消耗品、任务物品或全局掉落表。

金币使用临时占位图形表示；键盘 Z 或 HUD「拾取」按钮请求拾取附近金币。拾取距离和 180 秒寿命为当前本地适配，不宣称等同该服运行配置。

本地存储使用版本化单快照 `mxd.profile.v1` 及上一份备份，首次读取兼容原 `mxd.gold/cls/owned/equip/hair/outfit`，不删除旧键；损坏主快照可回退备份。保存失败写错误日志并向 UI 暴露状态。PlayerPrefs 不是文件事务或云存档；异常断电可靠性未做保证。

主角冷却由角色会话持有，大厅往返、同进程内重建主角和死亡重试都不能提前清除；目前未保存跨进程的冷却截止时间，退出游戏后冷却会重置。

原端装备是独立实例，可带不同随机属性；当前列表允许同 ID 多份，但没有装备实例属性、出售、叠加道具或完整背包 UI。原武器 ID/价格/属性已接入五个城镇商店的武器子集，详见第二阶段。

3. 完整怪物增益/免疫、元素状态及高级技能专属分派。召唤/突进现状见第二阶段。

### 属性与伤害

- `CharacterAttributes` 存储 STR/DEX/INT/LUK、等级、HP/MP、物防/魔防、命中/回避、熟练度和暴击参数；旧档没有这些字段时采用 `Character.getDefault` 的 Lv.1 / 12、5、4、4 / HP50、MP5，不凭空赠送等级、被动或高级技能所需 MP。
- 出战时快照基础属性，原武器 `incSTR/DEX/INT/LUK/PAD/MAD/PDD/MDD/ACC/EVA/MHP/MMP` 参与属性合成。总魔攻为 INT + 装备 MAD，上限 2000；愤怒之火加入 WATK 池后再计算物理伤害，不再直接增加最终伤害。
- `Character.calculateMaxBaseDamage`、`WeaponType` 和 `ItemInformationProvider.getWeaponType` 的武器倍率/主副属性选择已接入。魔法上界采用 `AbstractDealDamageHandler` 的公式，**仍是原服校验上界，不是已证明的客户端随机公式**。
- 当前 7 种怪物的原始等级、HP、PAD/PDD/MAD/MDD、命中、回避、元素抗性已导出；普通怪和 Boss 生命、接触攻击改用这些数值。Boss 跳砸等章节专用行为仍使用章节配置，不冒充原怪物全部技能。
- 本地已接上逐段随机、熟练度、命中失败、物理/魔法防御、元素免疫/抗性/弱点及攻击方暴击，所有攻击统一返回 `DamageResult`，接收方不重抽。
- **无法据现有源码证明的部分**：普通伤害由原 EXE 算好后上传，服务端没有其完整客户端公式。当前本地分布采用物理最小值 `(倍率×主属性×0.9×熟练度+副属性)×WATK/100`，魔法最小值为上界 50%；等级差每级 1%，怪物物防平减 0.5、魔防平减 0.6；玩家受击采用 85%–115% 攻击随机值并减防。命中使用 `accuracy / ((1.84+0.07×等级差)×怪物回避)`；元素强抗 0.5、弱点 1.5、免疫 0。这些是**显式单机适配策略**，不能称作与该服 EXE 完全相同。也尚未覆盖所有职业被动、火眼、套装/链接及 Buff 叠加次序、玩家回避公式、升级/AP/药品、完整装备栏。不存在学习记录时暴击率为 0。

### 独立召唤物

`NativeSummon` 是独立场景对象，持有自己的位置、朝向、原点、动画、攻击时钟和寿命。原 `StatEffect.getSummonMovementType` 将2321020标为 FOLLOW；已导出 summoned/stand/fly/attack1/die 共56帧，保存每帧原 origin 和绝对 delay；导出到统一补边画布，避免原点超出原图时被 Unity 轴心裁切。资源采用项目现有 Art/*.bytes 路径。攻击从召唤物的位置和朝向读取 `summon/attack1/info/range`，目标数取该 info 的6只，周期为原攻击动画总时长加 attackAfter660ms。伤害使用主人属性和原召唤技能等级参数。死亡、地图切换、重试、大厅和寿命到期会清理召唤，重召不会叠加旧对象。

跟随速度沿用主人步速、停距48px；服务端只定义 FOLLOW 并接收客户端移动，未提供精确移动曲线。这两个值属于本地适配。当前为飞行跟随，没有地面行走碰撞；到期直接清理，die帧已保留但不延长召唤寿命播放。

### 突进

1121006现在实际驱动玩家位移，逐步沿用 `StepMovement` 的8ms子步、竖直墙阻挡、斜坡支持和离边下落；输入不覆盖突进方向，不增加无敌。沿途每个目标最多结算一次该技能的段数，整次施法不超过原目标数；取消动作同步取消剩余位移。

原 WZ 1121006只有攻击框、伤害、MP等参数，没有独立突进速度/行程；服务端也依赖客户端移动包。因此本地最大行程取前向框宽160px，耗时取原人物施法动作。**这实现了突进功能与碰撞，不证明160px及运动曲线就是该 EXE 的最终运动参数**。

## 触屏技能回归修复

用户明确选择当前单机阶段暂不消耗MP，保留原技能冷却。原MpCost数据继续保留，但TryCast不再检查或扣除MP；不修改原端资源。触屏技能由TouchPad.Update逐根处理TouchPhase.Began，并在摇杆/跳跃之前消费技能按钮区域，支持按住摇杆时用另一根手指点技能。GameHUD.OnGUI只绘制技能，不再通过鼠标模拟或数字键施法，也不再显示数字键角标。冷却、攀爬、动作锁等拒绝原因显示在技能栏上方。

此选择覆盖本文之前关于MP不足阻止当前单机技能的说明；未来正式接入角色成长时再统一恢复MP玩法，不能将这项单机选择宣称为原服机制。
