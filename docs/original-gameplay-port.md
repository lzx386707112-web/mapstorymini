日期：2026-10-21。依据为本机 `/Users/lizixian/Documents/mxd/BeiDou-Server/gms-server/src/main/java/org/gms/` 与 `clien/Data`，原端文件只读。

## 技能语义修正与边界

- 防御崩坏走驱散/封技路径，不造成横扫伤害；当前怪物尚无增防/免疫增益系统，因此不能据此声称已完成所有驱散效果。
- 圣光恢复为魔法攻击，移除自我治疗；愤怒之火使用 WZ 的固定攻击增益与持续时间，移除 +60%/6 秒设定。固定增益现已加入 WATK 属性池；完整边界见下文第二阶段。
- 磁石不造成范围伤害或眩晕，只处理普通怪的拉近；Boss 不被拉动。拉近运动仍为单机适配，未核实原客户端运动曲线。
- 技能伤害段数、目标数、MP、冷却、攻击框和控制时长读取 Lv.1 参数；虎咆哮按概率眩晕，连环爆破按原 StatEffect 的冻结类状态使用双倍时长。现有 Stun 只提供停止行动的基础效果，尚未实现完整怪物状态系统。
- 剑影分身使用独立子技能 1121021/1121022，并按 `CloseRangeDamageHandler` 的 12 次斩击与 5 次爆炸时间表安排延迟攻击；斗气死亡断层延迟 1000ms 命中。
- 天秤之使改为有持续时间的周期攻击，召唤间隔取原 summon/attack1 帧延时与 attackAfter。现已实现独立实体、跟随、寻敌和原帧动画，详见第二阶段。
- 突进已移除自定义无敌帧，使用原技能攻击参数与推怪路径；角色自身突进与碰撞现已接入，原 EXE 参数核实边界见第二阶段。

- **无法据现有源码证明的部分**：普通伤害由原 EXE 算好后上传，服务端没有其完整客户端公式。当前本地分布采用物理最小值 `(倍率×主属性×0.9×熟练度+副属性)×WATK/100`，魔法最小值为上界 50%；等级差每级 1%，怪物物防平减 0.5、魔防平减 0.6；玩家受击采用 85%–115% 攻击随机值并减防。命中使用 `accuracy / ((1.84+0.07×等级差)×怪物回避)`；元素强抗 0.5、弱点 1.5、免疫 0。这些是**显式单机适配策略**，不能称作与该服 EXE 完全相同。也尚未覆盖所有职业被动、火眼、套装/链接及 Buff 叠加次序、玩家回避公式、升级/AP/药品、完整装备栏。不存在学习记录时暴击率为 0。

### 独立召唤物

`NativeSummon` 是独立场景对象，持有自己的位置、朝向、原点、动画、攻击时钟和寿命。原 `StatEffect.getSummonMovementType` 将2321020标为 FOLLOW；已导出 summoned/stand/fly/attack1/die 共56帧，保存每帧原 origin 和绝对 delay；导出到统一补边画布，避免原点超出原图时被 Unity 轴心裁切。资源采用项目现有 Art/*.bytes 路径。攻击从召唤物的位置和朝向读取 `summon/attack1/info/range`，目标数取该 info 的6只，周期为原攻击动画总时长加 attackAfter660ms。伤害使用主人属性和原召唤技能等级参数。死亡、地图切换、重试、大厅和寿命到期会清理召唤，重召不会叠加旧对象。

跟随速度沿用主人步速、停距48px；服务端只定义 FOLLOW 并接收客户端移动，未提供精确移动曲线。这两个值属于本地适配。当前为飞行跟随，没有地面行走碰撞；到期直接清理，die帧已保留但不延长召唤寿命播放。

### 突进

1121006现在实际驱动玩家位移，逐步沿用 `StepMovement` 的8ms子步、竖直墙阻挡、斜坡支持和离边下落；输入不覆盖突进方向，不增加无敌。沿途每个目标最多结算一次该技能的段数，整次施法不超过原目标数；取消动作同步取消剩余位移。

彩虹岛清单不按地图 ID 区间猜，取 `String/Map.img` 里 `streetName=彩虹岛` 且有对应 `Map0/<id>.img` 文件的条目，共 37 张。其中 0 号「蘑菇村西入口」是该服自建的教程入口（`onUserEnter=goAdventure`，20 个瓦片、13 个 foothold），4 号图与 `2000001 사우스페리 방어구상점` 同样是该服数据，照原样保留，不改名、不补图。

### 渲染

- 地图主体按 `VR ± 200px` 的包围盒分块渲染，块内是原 `Tile`/`Obj` 的真实像素与各自 `origin`，不做镜像、拉伸或补土。块坐标由 JSON 的 `pos/size` 还原。
- 远景按 `back` 的 `x/y/origin/rx/ry/cx/cy/type/alpha/front/no` 逐字段还原：`rx/ry` 参与相机视差，`type` 4/5/6/7 额外按 `5×|r| px/s` 自动滚动，`cx/cy` 为平铺步长，`front` 决定压在 600+ 还是 -800+ 排序层。滚动速率依据 `docs/original-map-rendering.md` 记录的 EXE/ weather-compat 反查结果。
- 图层排序沿用：远景 `-800+no`、地图主体 `-400`、NPC `100`、角色/怪物 `300`、前景 `600+no`。
- `life/hide=1` 的 NPC 不绘制（例：10000 小蘑菇的 2007，该 NPC 在 `Npc.wz` 里也没有素材），与原客户端一致。

### 刷怪（依据 `SpawnPoint.java` / `MapleMap.respawn`）

- 载入地图时每个刷怪点立刻生成 1 只。
- 每 `respawn_interval`（10s）补一次，目标数为 `ceil(getCurrentSpawnRate(玩家数) × 刷怪点数)`，其中 `getCurrentSpawnRate = 0.70 + 0.05×min(6, 玩家数)`，单人即 75%；`use_enable_full_respawn=false`。存活数达到目标就不再补。
- 单个刷怪点：`mobTime<0` 永不再生；`mobTime>0` 死亡后按 `mobTime` 秒解禁；`mobTime==0` 按死亡动画时长（`die` 帧总延时）解禁。一个点同时只挂一只怪。
- 补怪前按 `use_monster_random_refresh_position=true` 洗牌刷怪点顺序，避免固定只补列表靠前的点。
- 出生位置取刷怪点 `(x, cy/fh)`，落到脚下 foothold；巡逻范围取 `rx0..rx1`。
- 怪物 HP/攻击/速度/经验全部取 `Mob.wz/info`（`maxHP`、`PADamage`、`speed`、`exp`），数值本身不造。速度从 WZ 的百分比换算成 px/s 这一步属于本地适配，见下节与适配表。

### 怪物移动（速度换算与血条）

- `Mob.wz/info/speed` 是**相对 100% 的百分比偏移**：WZ 里以字节存，负值表示比基准慢（蜗牛 -65 = 35%），社区改速度就是把它改大（改成 126 明显变快）。本地把 100% 定为角色 `Character.wz` 的 `info/walkSpeed`（125px/s），两边同一套语义：

| 怪物 | `info/speed` | 换算后 |
|---|---|---|
| 蜗牛 100100 | -65 | 43.8 px/s |
| 木妖 130100 | -70 | 37.5 px/s |
| 蓝蜗牛 100101 / 红蜗牛 130101 | -50 | 62.5 px/s |
| 蘑菇仔 120100 | -30 | 87.5 px/s |
| 绿水灵 210100 | -20 | 100 px/s |
| 花蘑菇 1210102 / 9500102 | 0 | 125 px/s（与角色基准同速） |

- 巡逻与追击用**同一个**速度。旧版 `Roam` 里在换算结果上又乘了 0.35，蜗牛实际只有 9.8px/s（0.245u/s），看起来像站桩——这是「怪物移动很慢」的直接原因，已删除。公式收敛到 `FieldDirector.MobSpeed(wzSpeed)`，运行时与自检共用。
- 自检断言：`speed=0` 必须等于 125px/s、`speed=-65` 必须等于 43.75px/s，11 种怪都必须带 `speed` 字段。
- 血条按原端规则「**受伤才出现**」：满血不画。之前每只怪头顶常驻一根绿条，看起来像所有平台上的怪都在挨打（用户截图里连最上层四只蜗牛都顶着血条）。

### 普攻判定（横向 + 纵向）

- 普攻判定是矩形：横向 `±2.3u`（92px）、纵向 `±1.2u`（48px），以双方脚底为准，实现为 `PlayerCtrl.InMeleeBand`。
- 旧版只比横向距离、完全不管高度，而原版地图模式下所有怪与玩家都被固定成同一 `lane`，`lane` 过滤等于失效 → **站在最下层可以把最上层平台的怪打下来**（用户截图）。
- 高度取 48px 的依据：全地图 foothold 统计里，同一层台阶/斜坡的相邻高差都在 1.2u 以内，而层与层之间（例如 40001 的三层台）是 4.5u 量级；自检遍历 294 个刷怪点的所有两两组合，**2569 组跨层配对全部判不到**，而 1.0u 高的斜坡同层目标仍能命中。
- 技能不走这套判定：技能的 `lt/rb` 直接取 `Skill.wz` 的攻击框（`NativeSkillDefinition.Min/Max`），命中框多高由原数据决定，本地不改。

### 掉落（依据 `MapleMap.dropItemsFromMonsterOnMap` / 全局掉落）

- 判定阈值 `Randomizer.nextInt(999999) < chance`；条目先洗牌再逐条判定。
- 金币（`itemid=0`）数量 `nextInt(Max-Min)+Min`，即 `[Min, Max-1]`。
- 非装备数量 `Max(1,Min) + nextInt(Max-Min+1)`，即 `[Min, Max]`。
- 全局掉落数量用 `rand(min,max)`（两端都含），且 `itemId=0` 的条目不生成金币。
- 落地横向偏移按原 `getPos`：`d` 偶数 `+25×(d+1)/2`、奇数 `-25×(d/2)` 像素。
- 同一 `(怪物, 物品)` 只保留 SQL 里首条（`INSERT IGNORE` 语义），`chance=0` 视为永不掉落。
- 判定实现集中在 `FieldLoot.Roll`，运行时和自检共用同一份代码，不存在两套规则。

### 传送门

- 只处理 `pt=2`（地图间）与 `pt=10`（同图上下通道）。与原端一致：**站在门上按 ↑ / W（或摇杆向上）才进入**，走上去不会自动传送。早期版本为了照顾触屏改成「站 0.3s 自动进」，等于改变了原玩法，已去掉。
- **光洞贴图不在 `Map0/<id>.img` 里**：原端 `pt=2` 的门画的是 `MapHelper.img/portal/game/pv` 的 8 帧循环动画，地图数据只存 `x/y/pt`。所以「能按 ↑ 进、屏幕上却看不到门」的根因是这组帧从来没被导出过。现在由 `tools/wz_field.py --portals` 导出到 `art/map/field/_portal/pv_*.png` + `Resources/Field/FieldPortals.json`，`FieldView.Portal` 在 `sortingOrder=200`（地图主体之上、NPC/角色之下）循环播放。全彩虹岛 `pt=2` 门共 48 个。
- `pt=0/1/3/9` 在原端都是隐形的（出生点、隐形门、隐藏门、脚本隐形门），不画光洞；`pt=6`（changeable，彩虹村地面那 6 个 `tp`）也不画。
- WZ 的 pv 帧只有一个 `origin`、没有 `delay`，帧延时取 120ms（与 `wz_assets.py` 对「无 delay 帧」的同一约定），登记在下方适配表。
- 触发后必须先离开门（`portalArmed` 复位）才允许再次触发，避免出生点正好在门上、或进门后落点也是门时来回弹。
- HUD 在踩到可用传送门时显示「按 ↑ / W 进入传送门」。
- 目标点名不存在时按 `Character.changeMap` 的 `pto = to.getPortal(0)` 回退到目标图 portal 列表首条。原数据本身有 10 处悬空 `tn`（例如 `40001 west00 → 40000 east00`，而 40000 只有 `out00`），这是数据事实，本地不擅自改写地图数据。

### 换图渐变（`ScreenFade` + `FieldDirector` 的换图状态机）

原版从按下 ↑ 到人物出现在新图不是一个瞬间的硬切，而是一段黑场：**画面渐隐 → 换图 → 渐显**。本地早先是硬切，用户反馈「有点突然」。

- 三段时长：渐隐 0.32s、全黑停留 0.06s、渐显 0.32s，合计 0.70s。这段在原客户端是 `CField::TransferField` 里硬编码的——服务端源码、`Map.wz`、`MapHelper` 都没有「换图淡入淡出时长」字段（`BeiDou.exe` 的符号表也被抹掉了，连 `TransferField`/`Fade` 字符串都搜不到），所以三个数只能是本地取值，已进下方适配表。
- 换图**只在全黑那一帧发生**：`WarpState.Out` 把 alpha 推到 1 → 调 `Enter()` → `Hold` → `In`。推进用真实时间（`unscaledDeltaTime`），命中顿帧（`timeScale=0`）也不会卡在黑屏里。
- 用逐帧状态机而不是协程：实测协程里的 `WaitForSecondsRealtime` 在 batchmode / 切图卡帧时会让黑幕停在 alpha=1，换图就再也走不完。状态机每帧推进，行为可预期。
- 渐变期间 `PlayerCtrl.InputLocked = true`：不读输入、不跑物理（`SyncTransform` 仍执行，新图出生点才会立刻生效），避免黑屏里角色继续走或掉下平台。
- 同图内部传送（`pt=10`，例如选择之岔路的上下通道）与死亡复活（回 `returnMap` 的出生门）走同一段渐变。
- 黑幕用 IMGUI 画（`GUI.depth = -1000`），盖住 HUD、摇杆、技能格——原版切图时整个画面（含 UI）都是黑的。
- 黑幕启动时顺带给 0.9s 无敌：原版按下 ↑ 后人物立刻离场，本地还有 0.3s 站在原地，不该白挨打。

### 绳梯 / 绳子（`PlayerCtrl.StepClimb`）

- 数据取 `Map0/<id>.img/ladderRope`：`x`、`y1`（顶端）、`y2`（底端）、`l`（1=梯子 0=绳）、`uf`（顶端有可站平台）。全彩虹岛 109 条。
- 站在绳梯脚下按 ↑ 抓住并吸附到绳身上，按住 ↑/↓ 升降；到顶端且 `uf=1` 时自动站上平台；按跳跃键脱手；绳上按左右 + 跳跃也可以跳离。
- 抓取横向 ±10px。纵向给 100px 容差，因为 `y2` 是绳子**图元**下端而不是落脚点：全量统计 88 条绳底与地面差 ≤40px、17 条 40~80px、3 条 80~120px、1 条 213px（`1020001`）。容差覆盖 108/109 条；剩下 `40002 x=1059`（差 107px）属于原数据「绳底悬空」，只能从上方爬下来。
- 曾有一个导出缺陷：`ladderRope` 在部分地图里是 `<id>` 直挂、在另一些里多一层 `<page>/<id>`，旧脚本按固定两层遍历，把属性节点当条目，导出的坐标全是 0 → 运行时一条都抓不到。现在改为「节点自带 `x`/`y2` 数值子节点才算条目」的递归探测，并在自检里禁止「坐标全 0」的条目。

### 地面跟随（`PlayerCtrl.FollowGround`）

- 原端 foothold 用 `prev`/`next` 串成连续可走路径。运行时按「**端点重合（1.5px）即视为同一块地面**」跟随：段内线性插值，跨段直接接续，不再用高度差阈值判定。
- 早期实现要求「高度差 ≤ 0.6u（24px）才算有支撑」，台阶差超过 24px 就判成踏空；若该 x 下方又没有别的段接住，角色会一路掉到地图外（`FindLanding` 全部失败）。这是「走台阶掉到屏幕最下面」的根因。
- `GroundAt` 在 x 不落在任何段内时退回「水平最近段」的高度，避免传送门/出生点贴在平台边缘外一两像素时直接浮空。
- 兜底：脚底低于 VR 底部 4u 时复位到水平最近的地面（原端由服务端复位）。自检断言：2740 个「数据上端点相接」的接缝全部可走。

### 等级 · 经验 · HP/MP 与底部状态栏

经验与升级全部按原服务端 `Character.java` / `ExpTable.java` 复刻，数值不在本地估算。

- **经验曲线**：`ExpTable.java` 的 `exp[]`（250 项）原样导出到 `Resources/Field/ExpTable.json`（`tools/wz_exp.py`）。`getExpNeededForLevel(level) = exp[min(level, 249)]` 的截断也一起复刻，满级之后一律取表尾 2,100,000,000。
- **等级上限 255**：`V2.1.50__raise_character_level_cap_to_255_and_rebirth_cap_to_10.sql` 把 `mxj_max_level` 从 200 改到 255；导出脚本直接读这条 SQL 取值，不写死。
- **升级成长**（`Character.levelUp()`，`Randomizer.rand(min,max)` 上下界都含）：

  | 分支 | +HP | +MP |
  |---|---|---|
  | 初心者 | 12~16 | 10~12 |
  | 战士（骑士） | 24~28 | 4~6 |
  | 法师（法师/牧师） | 10~14 | 22~24 |
  | 弓手 / 盗贼 | 20~24 | 14~16 |
  | 海盗 | 22~28 | 18~23 |

- `use_randomize_hpmp_gain=true`：非法师 MP 再加 `INT/10`，法师加 `INT/20`。
- `use_level_up_protect=true`：一次经验结算最多升 **1 级**（本地 `LevelSystem.LevelUpProtect`）。
- `level_up_ap_gain=5` / `level_up_sp_gain=3`：每级累计 5 AP、3 SP；加点面板尚未做，AP 只累计。
- **满级经验封顶 99%**（`getMaxLevelExpLimit`），避免经验条画到 100% 以上。
- **升级回满**：`Character.levelUp → changeHpMp(localMaxHp, localMaxMp)`，本地在 `PlayerCtrl.ApplyProgression()` 里同样直接回满。
- **旧存档迁移**：老版本只累加 `experience`、从不升级。读档时 `LevelSystem.Reconcile` 按原曲线把累计值补成等级——本机实测存档（469 经验 / Lv.1）补成 **Lv.6 / 余 136**，自检里有这条断言。

**MP 消耗**取 `Skill.wz` 对应等级的 `mpCon`（`NativeSkillDefinition.MpCost`），不够时直接拒绝施法（原端 `TryUseSkill` 同样先判 MP、后扣蓝）。**自然回复**见下方适配表：原服务端只有椅子/技能 buff 的 tick，没有自然回复，自然回复属于客户端行为。

**底部状态栏**（`StatusBar.cs`）全部用 `UI.wz` 的原画：

- 底板 `StatusBar.img/base/backgrnd2` 是「聊天条 + 状态栏」一整块（570×71）：`y 7..28` 是全白半透明的聊天文字底板、`y 29..35` 完全透明、**`y 36..70` 才是状态栏面板**。本地没有聊天窗口，留一条空白白条只会像 bug，所以导出时裁出 `570×35` 的面板（整块另存 `bar_lv_full.png` 备查）。
- 三段槽是 `gauge/bar`（340×31，上排 `HP`/`MP`/`EXP` 文字 + 下排填充）按像素切出来的，外框 + 刻度用 `gauge/graduation` 同尺寸叠在上面；等级数字用 `Basic.img/LevelNo`（11×13 橙字）；槽内数值用 `StatusBar.img/number`（数字 5×7、斜杠 7×7、方括号 2×9），和原版一样写成 `[384/435]`。
- 排版常量按原图实测：面板左段 `x 0..207`（胶囊 `x 22..76` / `y 14..31` 放等级，名字从 `x 82` 起、职业在上名字在下，与原版截图 `Wizard` / `GoldMagician` 的顺序一致），右段 `x 209..562` 放三条槽（`x 216` 起、`y 2`，宽 109 + 108 + 123 = 340）。
- 缩放 `S = 虚拟高 / 600`：原版是 800×600 下的 1:1，本地 `UiKit` 把高度固定成 720，所以 1280×720 下取 1.2 倍，状态栏与地图贴图的像素才同级；窄屏按宽度收，不会顶出屏幕右边。
- 三条槽按原版顺序分三层画：**空槽底色 `gauge/gray`（1×16 的 #CCCCCC）→ 按比例裁剪的 `gauge/bar` 填充 → `gauge/graduation` 外框与刻度**。少了第一层，没填满的那段会直接露出深色面板（实测截图一眼就能看出来）。
- 填充用 `GUI.BeginGroup` 硬裁剪（不是缩放贴图），像素不会被插值糊掉。
- 技能格从原来的「底部居中」挪到**右下角**；横排放不下时整排抬到状态栏上方，绝不压在血条上。

### 键盘与虚拟按键（`InputHub.cs` / `VirtualPad.cs`）
- 动作与按键解耦：游戏逻辑只问 `InputHub.Held(GameAction.Jump)`，物理键盘和屏幕按键走同一条路径，
  重绑一个虚拟键 = 换一个 `KeyCode`，逻辑一行都不用改。
- 默认键位按原版：方向键移动、**Alt 跳跃、Ctrl 攻击**、Z 拾取、E 装备、I 背包、S 能力值、K 技能、
  F2 键位、` 快捷栏、Tab 快捷键、Esc 菜单、F1 帮助、F4 商城；
  八个快捷格 = **Shift / Insert / Home / PgUp / Ctrl / Delete / End / PgDn**。
- 虚拟键盘底图直接用 `UIWindow.img/KeyConfig/backgrnd`（629×373 的原版「键盘设定」全键盘），
  键帽矩形是从这张图逐像素量出来的（`tools/wz_keylayout.py` 里记录了量法：亮面二值化 + 四连通域），
  共 86 个键位、全部能映射到 `KeyCode`，自检里有「键帽数量 / 键名可识别 / 不越界」三项断言。
- 支持多指同时按住（`Input.touches` 逐根跟踪），所以能一边走一边跳一边放技能；
  长按 0.6 秒弹出动作列表，把这一格键改成别的动作（`KeyMap.Bind` 会保证一个键只服务一个动作）。
- 鼠标模式：整屏变触摸板，拖动移光标、轻点=左键，用来点技能窗/拖技能图标（Winlator 的鼠标模式同一套用法）。

### 显式适配（不等于原端行为）

| 项 | 本地做法 | 为什么不是原端 |
|---|---|---|
| 刷怪补位节奏 | 每 10s 一次，常量 `RespawnInterval` | 未接 `respawn_interval` 配置读取，取该服默认值 |
| 主动攻击距离 | `aggroRange = 320px` | 原服由客户端视野与怪物 AI 决定，服务端不定义 |
| 行走速度 | `125px/s × (100+speed)/100`，100% 取角色 `walkSpeed` | 原 EXE 的运动曲线不在服务端源码里；这里只做 WZ 百分比换算，不再额外缩放（旧版多乘 0.35，已删） |
| 巡逻/追击 | 玩家进入范围且高度差 ≤1.8u 才追，否则在 `rx0..rx1` 巡逻（与追击同速） | 原客户端怪物 AI 在 EXE 内，未反查 |
| 普攻纵向范围 | ±1.2u（48px） | 原端近战框来自武器/动作数据，本阶段未导出；高度按全地图 foothold 间距反推，保证够不到上层平台 |
| 怪物血条 | 满血隐藏、受伤后显示 | 原端是受伤才画；本地不做原端的淡出曲线 |
| 传送门触发 | 按 ↑ / W / 摇杆向上；触屏摇杆向上等价于原端「按上键」 | 原端只有键盘上键；摇杆映射是本地方便触屏，触发语义（必须主动按上、走上去不进）一致 |
| 绳梯抓取容差 | 横向 ±10px、纵向 100px，抓住后吸附到绳身 | 原端 EXE 内的精确抓取范围未反查；100px 由 109 条绳梯的实际 `y2` 与地面差分布反推 |
| 掉落复位 | 低于 VR 底部 4u 复位到最近地面 | 原端由服务端处理（回城/复位包），单机没有服务端 |
| 金币图形 | 程序化黄色圆点 | 原端金币素材未抽取（`Item` 里没有通用金币图标） |
| 装备类掉落图标 | 中性方块占位 | `Character.wz` 装备图标本阶段未导出 |
| 传送门光洞帧延时 | 8 帧各 120ms | WZ 的 `portal/game/pv` 帧只有 `origin`、没有 `delay`，取项目对无 delay 帧的同一默认值 |

| 相机插值 | 沿用项目现有指数平滑 | 未确认与原端 Shape2D 曲线一致 |
| HP/MP 自然回复 | MP 每 10s 自动回、最低 3 点（高等级按 `1% × maxMP` 递增）；HP 站立不动每 10s +10 | 原服务端没有自然回复实现（`recoverHP/recoverMP` 只服务椅子与技能 buff），自然回复在客户端里；数值取 Mapletip《MP》《Health Points》记载的最低速率，节拍沿用原版固定的 10 秒 |
