## 继续逆向核实（尚未接入的家族界面）

主窗口的按钮分派是 `0x91CF4F`（vtable+0x20）；`0x91EFC4` 是窗口身份判断，不是 OnButtonClick。
按钮 ID 与分派：2030邀请→`0x9111BE`；2032退出→`0x9112B4`；2031驱逐→`0x9112C0`；2033/2034升降职位→`0x911341`；2036悄悄话→`0x9113C0`；2037公告→`0x9114F1`；2038成员位置→`0x911454`；2039资料展开→`0x91E2E0`；2040组队邀请→`0x911687`；2041公告板→`0xA05AB8(11,-1)`。
升职传当前职位−1，降职传+1；当前成员等级和自己权限共同决定 disabled 状态，不能只套统一的 manager 开关。
资料按钮创建附属 GuildGrade 窗口（`0x915D7C`），窗口233×304，并传递主窗口位置；不能居中一个通用详情弹窗代替。
`0x9165DD` 依次在 x6/y8、45、91、128、146 复制 GuildGrade/guildgrade3、4、0、1、2。
五行职位每行18像素，数字 x26、人数 x66、职位名称在 x146起的86像素列内居中；修改/保存按钮(25,268)/(125,268)。
`0x916F28` 的职位名称输入最多10字符；rank1..3最少4字符，rank4..5可为空。现有服务端45字符校验与此客户端入口并不相同，迁移时需要分清约束层次。

`0x9111BE` 邀请输入最多12字符、最少4；`0x9114F1` 公告最多100字符。
两者使用 CUtilDlg type3：`0x9ACD54`、`0x9A3CAE`、`0x9A3DC1` 核实普通宽529，最低文本区120，高206；文本起点(157,28)。
输入控件 `0x9A83F6` 位于(159,153)，宽213、高14；OK(475,180)，关闭(9,180)。源端输入边框用 FillRect 绘制；用户已允许严格照搬核实后的原端绘制代码，禁止自行设计。
公告板使用独立 `UI/GuildBBS.img/GuildBBS`，主背景734×526，不是 UserList/Guild/GuildBoard 的旧网页素材，也不能用普通提示框替代。
`BBSOperationHandler.java` 提供新帖/编辑/删除/分页/回复/删回复，当前本地 Community 协议尚未迁移这部分。尚未完成的临时家族 UI 已撤回，避免将空壳按钮误交付为已完成。

## UserList Tab 控件后续证据

`0x919D34..0x919D46` 创建 x6/y23/width270 的 mode0控件。
`0x4DE15F` 对 mode0 使用 leading12、间隔13、trailing6；宽度分配还取决于+0x34的等宽开关，不能直接划成五个54px按钮。
`0x4DD903` 在每段右端绘制 middle，最后一段绘制 right，fill逐像素平铺；middle状态由本段或下一段是否选中决定。
位图标签由enabled/disabled节点提供，居中复制在段内；mode0不增加额外竖直偏移。该控件分析尚未作为完整家族界面交付。
