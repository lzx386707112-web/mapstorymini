`0x90F17C` 不是画在一张画布上，而是两张，**两个参数都是画布局部坐标**，直接当窗口坐标用会把徽章画到红线上（本工程踩过，用户截图里徽章压红线就是这么来的）：

| 元素 | 局部坐标 | 依据 |
| --- | --- | --- |

### 成员职业列 / 成员位置的数据来源

- 职业列：`GuildPackets.showGuildInfo` 每成员字段为 `name(13 定长) → job(int) → level → guildRank → online → signature → allianceRank`，**职业就是 jobId**，客户端按 `Job` 表显示中文名（源端 `Job.java` + `message_zh_CN.properties` 的 `job.name.<id>`，本工程已有一份 `Npc/JobEnum`）。列头位图 `GuildInfo/guildinfo2` 文字为「名字/职业/等级/地位」。
- 成员位置：包里**没有 map 字段**。源端是客户端本地成员表里的 mapId 再查 `String.wz` 的 `mapName`。本工程没有客户端侧成员表，改由服务端随 DTO 下发 mapId，客户端用 `String/Map.img/<大陆>/<mapId>/mapName` 还原同一段文字（`NativeMapNames.Of`，含 0~4 号新手区地图）。
- 家族徽章：`guilds` 表 `logo/logoColor/logoBG/logoBGColor` 四元组，包里的 `signature` 不是徽章下标，不要拿它当图案。

## 继续逆向核实（尚未接入的家族界面）

主窗口的按钮分派是 `0x91CF4F`（vtable+0x20）；`0x91EFC4` 是窗口身份判断，不是 OnButtonClick。
按钮 ID 与分派以上面的「id → 节点 → 桩 → 处理」表为准（**2035=BtWhere=成员位置，2038=BtChat**；旧记录把 2038 写成成员位置是错的）。
升职传当前职位−1，降职传+1；当前成员等级和自己权限共同决定 disabled 状态，不能只套统一的 manager 开关。
资料按钮创建附属 GuildGrade 窗口（`0x915D7C`），窗口233×304，并传递主窗口位置；不能居中一个通用详情弹窗代替。
`0x9165DD` 依次在 x6/y8、45、91、128、146 复制 GuildGrade/guildgrade3、4、0、1、2。
五行职位每行18像素，数字 x26、人数 x66、职位名称在 x146起的86像素列内居中；修改/保存按钮(25,268)/(125,268)。
`0x916F28` 的职位名称输入最多10字符；rank1..3最少4字符，rank4..5可为空。现有服务端45字符校验与此客户端入口并不相同，迁移时需要分清约束层次。

`0x9111BE` 邀请输入最多12字符、最少4；`0x9114F1` 公告最多100字符。
两者使用 CUtilDlg type3：`0x9ACD54`、`0x9A3CAE`、`0x9A3DC1` 核实普通宽529，最低文本区120，高206；文本起点(157,28)。
输入控件 `0x9A83F6` 位于(159,153)，宽213、高14；OK(475,180)，关闭(9,180)。源端输入边框用 FillRect 绘制；用户已允许严格照搬核实后的原端绘制代码，禁止自行设计。
公告板使用独立 `UI/GuildBBS.img/GuildBBS`，主背景734×526，不是 UserList/Guild/GuildBoard 的旧网页素材，也不能用普通提示框替代。
`BBSOperationHandler.java` 提供新帖/编辑/删除/分页/回复/删回复，当前本地 Community 协议尚未迁移这部分。尚未完成的临时家族 UI 已撤回，避免将空壳按钮误交付为已完成。

### 公告板的后续入口

`UI/GuildBBS.img/GuildBBS/backgrnd2`、`backgrnd3` 为327×288。原端 `0x92C38E` 通过字符串3742加载主背景，窗口 type11。

服务端依据为 `gms-server/src/main/java/org/gms/net/server/channel/handlers/BBSOperationHandler.java`，序列化进一步查 `GuildPackets.java`：mode0新建/编辑，标题最多25、正文最多600；mode1删除、mode2按page×10分页、mode3读帖、mode4回复最多25、mode5删回复。图标0..3，或100..106且持有5290000+icon−100道具。

以上是继续分析的确定入口，不代表公告板的完整显示、权限和状态转换已分析完。错误入口 `0x814200`、`0x814A00` 不应直接当作函数起点反编译。
## UserList Tab 控件后续证据

`0x919D34..0x919D46` 创建 x6/y23/width270 的 mode0控件。
`0x4DE15F` 对 mode0 使用 leading12、间隔13、trailing6；宽度分配还取决于+0x34的等宽开关，不能直接划成五个54px按钮。
`0x4DD903` 在每段右端绘制 middle，最后一段绘制 right，fill逐像素平铺；middle状态由本段或下一段是否选中决定。
位图标签由enabled/disabled节点提供，居中复制在段内；mode0不增加额外竖直偏移。该控件分析尚未作为完整家族界面交付。
