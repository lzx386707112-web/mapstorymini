## 小地图

原端 `0x856400`：模式 0=MaxMap，1=MinMap，2=Min；快捷键 `0x859108` 按 `(mode+2)%3` 切换。
原素材 `UI/UIWindow.img/MiniMap`：MaxMap 顶部72/底部15，MinMap 顶部29/底部14；Min 高20。
MaxMap/MinMap 使用 nw/n/ne/w/e/sw/s/se/c 九片，Min 使用 w/c/e 三片。
`0x8588FF`：canvas.width≥280 时视口210，否则原宽；canvas.height≥150 时视口112，否则原高。
`0x8563C1`：MaxMap 宽度容纳视口及两行文字；MinMap 宽度只容纳视口，最小120；Min 使用两行文字宽度总和+80。
字体宽度在 Unity 中由当前中文字体测量，不能宣称与原端 Windows 字体逐像素相同。
`0x8564AD`：视口水平居中。`0x856C6D`：模式0顶部偏移72，否则29。
`0x8583EA`：BtMap 在 W−42/y6；Min 模式 W−44/y4；BtMax 左移14，BtMin 左移27。
`0x857616`：title 复制到(8,10)，当前 IMG 的 title 为1×1。
`0x8576A4`/`0x857B18`：两行文字中心复制 y28、44，x8，有 mapMark 时另加40；相邻坐标是文字阴影。
`0x85817F`：`Map/MapHelper.img/mark/<info.mapMark>` 复制到(6,23)。
`0x85ABBC`：按玩家坐标计算滚动、以 mag 进行整数右移；`0x859313` 是裁切复制，不是将整张地图缩小。

已修改：原素材拼接、三种模式、快捷键循环、视口裁切/滚动、原生按钮与标记/徽标。
未完成：原端文字阴影的逐像素匹配、保存窗口位置/拖动及手机视觉对照。

## 小地图背景（2026-10-26 核实；此前「不透明底」结论作废）

**结论：源端小地图背景就是半透明的，不应铺不透明白底。**

- `UI/UIWindow.img/MiniMap/MaxMap|MinMap/c` 是 **1×1、RGBA(255,255,255,119)** 的半透明白片；
  地图 `miniMap/canvas` 本身也是透明底（100000000 实测 465×87、仅 49% 不透明，内容是灰色线稿+半透明地块，
  中排 alpha 序列含 0/187/170/210/255）。
- 因此原端外观 = 半透明白叠在游戏画面上，**能透出地图**，而不是纯白。
- 曾经按「与大地图 FillRect 同款」的推断加了整面板不透明白底，结果与源端不符
  （用户反馈自由市场小地图背景变成白色），**已撤销**。该推断没有源端依据，
  且大地图的 `FillRect(2,2,W-4,H-4,0xFFFFFFFF)`（0x9EC12A..0x9EC143）是**大地图**窗口的，
  不能直接套到小地图上。

**待核实（未下结论）**：小地图绘制中 0x859279 / 0x8592CD 两处 `call [reg+0x8c]`
（同一矩形 `(scrollX, scrollY, vportW, vportH)`，颜色常量 `0xffffff` 与 `0xa0000000`）
的目标对象与颜色格式尚未定死，不能据此断言背景色。

`0x8588FF` 常量已在当前 EXE 复核：`cmp ecx,0x118`(280)→`mov ecx,0xd2`(210)；`cmp eax,0x96`(150)→`push 0x70`(112)。
面板尺寸公式（+12/最小 0x78=120、高 +0x2B=43 / +0x57=87、Min 宽 +0x50=80、高 0x14=20）与运行时一致；
0x856487 起另有 0x30C(780)/0x244(580) 的上限 clamp，语义（量宽还是面板）未核实，运行时未加。

**标记素材（已核实存在）**：`Map/MapHelper.img/minimap/` 下有
`user`(6×6)、`another`、`friend`、`guild`、`guildmaster`、`match`、`party`、`partymaster`、
`npc`(4×7)、`startnpc`、`endnpc`、`usertrader`、`anothertrader`、`portal`(8×8)、
`arrowup/down/right/left/upright/upleft/downright/downleft`。

### 自由市场 910000000 小地图实测（2026-10-26）

- `miniMap/canvas` 246×143 **透明底**（23006/35178 像素 alpha=0，无白色底）；`width=3937/height=2289/centerX=1321/centerY=2044/mag=4`。
- 246<280、143<150，两个阈值都不触发 → 视口=原尺寸、滚动恒为 0，整张画布完整显示，无裁切。
- 标记齐全：8 个可见 NPC 绿点（x=83/190/288/420/580/850/1120/1450，y=23）+ 玩家黄点；portal 里 `pt` 分布 `{0:3,1:32,3:4,7:1}`，无 pt=2/7 → 只画 1 个标记的条件（type==2||7）实际一个都不满足，与原端一致。
- 所以「背景白」来自运行时多铺的不透明底（已撤销），**不是**数据或标记缺。

**教训（流程纪律）**：不得用截图/像素比对反推源端逻辑——截图只能用来发现
「与源端不符」的线索，真正的依据必须来自 EXE 反汇编、服务端代码或脚本。
上一版把推测写进 skill 记为「已核实」是错误做法。

`0x9EC2F6`至`0x9ECC49`：Border/0左上、1上条、2右上、3左条、4右条、5左下、6下条、7右下；左右7像素、底18像素。

运行时已删除自行填色底板及默认Unity按钮，使用上述节点和参数；原地图BaseImg保留原尺寸/origin。
用户已明确允许严格照搬已核实的原端代码绘制，禁止自行设计；据 `0x9EC12A..0x9EC143` 补回 IMG 边框下的白色内底 `FillRect(2,2,W-4,H-4,0xFFFFFFFF)`。
